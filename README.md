# Pi Calculator

Визуальное веб-приложение на `Spring Boot + React`, которое показывает процесс вычисления числа `Pi` в реальном времени. Каждая цифра появляется отдельно, крупным шрифтом, а над ней отображается время, за которое эта цифра была получена с начала вычисления.

## Что умеет проект

- вычисляет цифры числа `Pi` по одной;
- показывает цифры в браузере в виде горизонтальной ленты;
- над каждой цифрой отображает накопленное время вычисления;
- позволяет задать количество цифр после запятой;
- позволяет задать задержку между выводом цифр для красивой анимации;
- запускается локально через `Gradle` или в `Docker`;
- работает на порту `8181`.

## Технологии

- `Java 21`
- `Spring Boot 4`
- `Spring Web`
- `Server-Sent Events (SSE)` для потока цифр из backend в frontend
- `React 18` для клиентского интерфейса
- `Gradle` для сборки
- `Docker` для контейнерного запуска

## Как запускать проект

### Основной способ запуска

Требуется:

- установленный и запущенный `Docker Desktop`

Запуск одной командой:

```powershell
powershell -ExecutionPolicy Bypass -File .\run-docker.ps1
```

Что делает эта команда:

- собирает Docker-образ приложения;
- поднимает Docker-контейнер `pi-calculator-container`;
- публикует приложение на порту `8181`;
- ждёт, пока приложение станет доступно;
- автоматически открывает окно браузера со страницей программы.

После выполнения команды приложение должно открыться автоматически по адресу:

```text
http://localhost:8181/
```

### Готовая Windows-сборка

В репозитории можно собрать:

- готовый Windows installer `.msi`;
- удобный Windows launcher `.exe`;
- переносимую локальную сборку с уже встроенной `Java runtime`.

### Подготовка Windows для сборки

Чтобы в этом проекте можно было собирать Windows-дистрибутив, на Windows должны быть установлены:

- `JDK 21`

Проверка, что инструменты доступны:

```powershell
java -version

```

Если `candle.exe` или `light.exe` не находятся, обычно помогает:

- закрыть текущий терминал;
- открыть новый `PowerShell`;
- повторить проверку команд.

Пример установки через `Chocolatey`:

```powershell
choco install openjdk21 -y
choco install dotnet-sdk -y
choco install wixtoolset -y
```

После установки желательно открыть новый терминал, чтобы обновился `PATH`.

### Как подготовить Windows-дистрибутив

Порядок действий:

1. Откройте проект в `PowerShell`.
2. Убедитесь, что установлены `JDK 21`, `.NET SDK 9` и `WiX Toolset`.
3. При необходимости проверьте команды `java -version`, `dotnet --version`, `candle.exe -?`, `light.exe -?`.
4. Запустите сборку командой ниже.

Команда сборки:

```powershell
powershell -ExecutionPolicy Bypass -File .\build-exe.ps1
```

После сборки появятся:

```text
dist\PiCalculator-1.0.0.msi
dist\PiCalculator-Start.exe
dist\PiCalculator\PiCalculator.exe
```

Запуск:

- если нужен один файл для передачи другому человеку: используйте `dist\PiCalculator-1.0.0.msi`;
- это основной Windows installer;
- он устанавливает приложение вместе со встроенной Java runtime;
- после установки приложение нужно запускать не этим файлом, а через ярлык `PiCalculator` в меню `Пуск` или на рабочем столе;
- удобный локальный вариант для разработчика: `dist\PiCalculator-Start.exe`;
- это удобный Windows launcher без консоли;
- он сам найдёт portable-сборку и запустит приложение правильно;
- backend поднимется на `8181`;
- браузер откроется автоматически.

Важно:

- `dist\PiCalculator-1.0.0.msi` — основной установщик, а не само приложение;
- `dist\PiCalculator-Start.exe` — основной файл для запуска;
- `dist\PiCalculator\PiCalculator.exe` — это переносимая portable-сборка;
- если повторно запускать `msi` после установки, Windows покажет экран обслуживания/переустановки — это нормальное поведение для installer'а;
- для запуска нужен весь каталог `dist`, потому что `PiCalculator-Start.exe` использует папку `dist\PiCalculator`;
- если запускать внутренний `dist\PiCalculator\PiCalculator.exe` отдельно или после копирования одного файла, можно получить ошибку `Failed to launch JVM`;
- переносить нужно либо весь каталог `dist`, либо как минимум `PiCalculator-Start.exe` вместе с папкой `PiCalculator`.

### Как остановить программу

Если приложение было запущено через `Docker`, остановить его можно так:

```powershell
docker stop pi-calculator-container
```

Если нужно полностью удалить контейнер:

```powershell
docker rm -f pi-calculator-container
```

Разница:

- `docker stop pi-calculator-container` — останавливает контейнер;
- `docker rm -f pi-calculator-container` — принудительно останавливает и удаляет контейнер.

Если приложение было запущено через `dist\PiCalculator-Start.exe` или через `dist\PiCalculator\PiCalculator.exe`, его можно остановить через `Диспетчер задач Windows`, завершив процесс `PiCalculator.exe`.

## Принцип работы

Приложение состоит из двух частей:

### Backend

Backend на `Spring Boot`:

- вычисляет цифры числа `Pi`;
- формирует событие для каждой цифры;
- отправляет эти события в браузер через `SSE`.

Каждое событие содержит:

- порядковый номер символа;
- сам символ, например `3`, `.`, `1`;
- время в миллисекундах от начала вычисления до появления этого символа.

### Frontend

Frontend:

- открывает `EventSource` на endpoint `/api/pi/stream`;
- получает цифры по мере вычисления;
- добавляет каждую цифру в интерфейс;
- автоматически прокручивает ленту вправо по мере роста числа.

## Алгоритм вычисления числа Pi

В проекте используется spigot-алгоритм для десятичного разложения числа `Pi`.

Его идея:

- цифры вычисляются последовательно, слева направо;
- не нужно заранее получать всю строку числа `Pi`;
- каждая новая цифра появляется независимо, что удобно для потоковой визуализации;
- алгоритм хранит промежуточные остатки во внутреннем массиве и постепенно уточняет следующую цифру.

Почему выбран именно он:

- хорошо подходит для показа цифр по одной;
- не требует сложной арифметики с большими десятичными строками на каждом шаге;
- естественно сочетается с `SSE`, где удобно отправлять результат по мере вычисления.

- `GET /api/pi/stream?digits=300&delayMs=35` — поток цифр `Pi`
